## 3. 当前配置为什么允许等很久

### 默认思考与较大的输出预算

`src/wattbot/models.py` 的 get_mimo 没有设置 thinking 或输出上限。MiMo 官方文档说明，mimo-v2.6-flash 默认开启思考，默认 max_completion_tokens 为 131072，预算包含思考和最终答案；长思考增加响应延迟。[Chat API](https://mimo.mi.com/docs/en-US/api/chat)、[Deep Thinking](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/other/deep-thinking)。

目前只有独立读图后的协调调用显式关闭思考。查询规划、普通答案生成、逐图读数均沿用默认思考模式。

此外，思考模式下 MiMo 会将 temperature 强制设为 1.0、top_p 设为 0.95，因此代码中的 temperature=0 无法约束这类调用的实际采样参数。这与非思考对照的实际配置存在差异，不宜将相同代码视为确定性实验。[Chat API](https://mimo.mi.com/docs/en-US/api/chat)。

### timeout=120 不约束整题总时间

实际客户端为 HTTPX2，标量 timeout=120 对应连接、读取、写入和连接池等待等网络操作超时。读取超时约束下一段网络数据的等待时间，持续收到数据时不会累计成整个请求的墙钟截止时间。[HTTPX 超时说明](https://www.python-httpx.org/advanced/timeouts/)。

q029 的慢回答请求在约 8.14 秒返回 HTTP 200，此后以约五秒间隔持续收到很小的原始响应数据包，客户端仍留在第一次请求中。直到诊断结束，记录没有出现第二次 HTTP 尝试。因此，本次复现中的长等待无需 API 重试即可发生。传输记录统计 gzip 压缩状态下、解码前的原始字节；不能根据其中的 whitespace 标记直接判定解码后的响应内容。

max_retries=2 还允许符合 SDK 重试条件的网络／服务错误最多尝试三次。这可能扩大其他失败调用的总时间，但本次完成及被停止的请求都只观察到 retry=0。

## 4. 次要成本与测试长尾

- q029 的输入约 1.29 万 token：证据正文约 3.37 万字符，另外还有系统提示、结构化 schema 和核对规则。上下文较大，且包含多份相关论文的不同统计值。它可能放大推理难度，具体贡献尚未单独消融验证。
- 图表题可触发多个独立读图 API，缺失事实可触发补查和第二轮生成。这些路径会增加其他题的耗时；它们无法解释本次 q029 的首轮长等待。
- 本地检索使用锁；当前三题并发能重叠远程调用，已经开启。锁内每题约数秒的本地工作，在这两个小样中影响较小。提高并发无法直接缩短某道题自身的数分钟生成。
- 每次启动独立小样进程，约有 10 秒导入及 3 秒模型初始化。代码未变化的对照题可在同一批运行；单独启动太多次会重复付出固定成本。
- 原回归脚本只记录整题总时间，完成一题后才打印结果。慢调用期间缺少阶段反馈，容易显得一直没有进展。临时诊断脚本补足了此次观察，生产逻辑没有新增监控框架。

历史 245 题全量记录：中位数 44.39 秒，均值 70.79 秒，P90 138.47 秒、P95 197.20 秒，最长 876.20 秒。32 题超过 120 秒，9 题超过 300 秒。后者占 3.7% 的题目，却占累计题目时间约 22.6%。这些是历史版本的记录，包含并发等待，累计题目秒数不能当成批次墙钟时间，也不能直接外推当前代码全量用时。

## 5. 建议处理顺序

1. **先验证思考策略。** 查询规划先评估关闭思考；答案生成用一小组固定题比较关闭／开启，覆盖原正确题、多论文计算、范围／极值、图表和拒答。核对答案值、引用 F1 和时长。只有验证质量后才改变默认配置；复杂题需要思考时再保留有界调用。
2. **再设输出边界。** 避免沿用 131072 的默认预算。上限包含思考和最终 JSON，本次 4096 已出现截断，不能直接全局照抄。须给最终结构化答案留空间，并明确处理 length 结束原因；不把截断冒充主动拒答。
3. **减少重复测试成本。** 生成／引用处理改动先用相同真实证据做生成对照，再做小批全流程回归。检索逻辑变化仍需完整检索验证。代码变化继续使用独立结果目录，避免新旧结果混合。
4. **最后再精简上下文和额外请求。** 通过对照验证选择更少的重复页面／无关来源，以及逐图、补查是否确有必要。不要直接删除算术操作数、限定条件或另一篇论文来换取速度。

暂不优先：重建索引、更换 GPU、压低召回候选数、添加更复杂的并发框架。此次定位已表明它们对生成长尾的直接帮助有限。

本轮四个诊断进程均已结束；没有后台测试继续运行。原索引及预测／提交文件未改动。
