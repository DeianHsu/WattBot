## 2. 五步改动

### 第一步：事实级证据融合

- 查询规划新增 `fact_id`；同一事实的同义查询共用编号。
- 每路重排后保留全部去重候选参与融合，避免先裁成十份再合并。
- 每个事实按 `1 / (60 + rank)` 投票，同事实多个改写只取最高票，避免改写多就占优势。
- 每个必要事实先保留最多两份高排名证据，再按融合排名补足 Top-10；整题查询没有额外事实配额。
- 候选到最终证据均按 `evidence_id` 去重，原始表格和图片不会被重复块占满。

这保留了跨事实覆盖及共同命中的证据，但检索命中不等于该证据充分支持事实；模型仍须判断内容与条件。

### 第二步：精确实体与版本排序

- 规划提取原题中明确出现的实体，程序只接受原题及对应查询中确有的完整名称。
- 名称匹配保留字母、数字、版本及后缀边界，宽容空格和连字符差异。
- 关键词召回为完整实体预留少量名额，重排后只给予有限排名加分。
- 保留没有实体名的设置段落及宽泛召回结果，不使用硬过滤。

离线真实 SQLite trigram 夹具验证了前缀误命中不会挤掉完整名称。此规则无法解决省略名称、未知缩写或实体歧义的所有情况。

### 第三步：有限上下文扩展

- 必要事实各自优先获得原始页面锚点，再按原有相关性补足三个页面。
- 选页面时比较各事实自己的查询内最佳排名，低排名跨事实命中不抢占另一事实的页面；补查编号独立于首轮及其他补查。
- 保留对应论文首页，恢复文档身份及研究对象。
- 按现有正文块序号取回前后原文；同页已发送完整页面，不重复追加，仅补跨出这些页面的原文，最多四块。
- 不递归扩展，不新增检索模型、重建索引或生成“上下文摘要”。

这一层恢复更多条件和跨页连接，无法保证任意远距离条件都进入上下文。

### 第四步：最终模型保留原图

- 保留现有逐图隔离读取和程序绑定来源 ID。
- 最终回答同时收到独立读数及最多两个非空读数来源各一张原图。
- 原图紧跟对应 E-label、论文及页码；其他已读图沿用读数，空读数不额外附图。
- 提示最终模型优先服从原图、图例与原文条件；程序不依据读数标记修改答案或拒答。

这降低摘要丢失面板、图例和适用范围的风险，仍受视觉模型读图能力影响；图表题小样没有出现新的答案值提升。

### 第五步：邻近脚注与高置信续表

先只读检查现有 573 份表格，找到 24 对相邻页相同表头的候选。相同表头只用于核查，不能单独证明延续关系。

脚注处理：

- 依据同页栏位重叠和垂直距离收集邻近原始脚注，排除另一栏脚注。
- 没有可靠版面时，只沿用唯一显式引用；关系不清楚的脚注仍保留为独立正文。
- 脚注进入检索正文和原始 metadata，避免被短前缀预算截断。
- 明确提醒模型按脚注标记确定它限定表格或周边正文，不默认每条邻近脚注都适用。

续表处理：

- 首部分必须有明确表题，后续部分没有新表题，或明确使用相同表号的 continued 标记。
- 相邻页面、同栏、原始多级表头和单位一致；中间出现新正文时停止推断。
- 要求上一部分接近页末、下一部分接近页首。
- 成组部分共享首部分 `evidence_id`，保留各部分原文、页码和截图；不重新计算或填补单元格。
- 表头异常或关系无法确认时保持独立表格，继续原有单表处理。

局部真实文档验证使用 CPU 和已有模型缓存，没有调用 API 或写入真实索引：

## 3. 仍存在的质量缺口

1. **q220 两组均错。** 新版本已经召回 `li2025b:text:38`，其中给出美国平均耗水强度 3.14 L/kWh；模型仍选择另一来源排除水电的 1.8 L/kWh，输出 1.98。当前剩余缺口涉及统计范围及证据选择，检索已取得相关段落。不能据此添加该题特例或让程序覆盖 LLM 计算结果。
2. **表格局部漏字仍未完全解决。** GAO 两页真实 Docling 结果中，Data filtering、Red teaming 行标签为空，其他行仍有可解析内容。续表归组不会重建这些标签；原图继续保留。Amazon 第 26 页也可见局部空单元格及粘连。现有“整表长列表粘连”启发式无法覆盖这些问题。
3. **解析规则仍有误判边界。** 几何脚注可能属于附近正文；不满足严格条件的真实续表会漏合并，满足规则的两个独立无题表也可能误合并。当前验证覆盖了真实正例和合成负例，尚未全量审计。
4. **小样不足以保证泛化。** 未运行全量训练预测或全量测试预测，没有证明每项修改单独提分，也未完成扩大控制集的回归验证。
5. **必要引用仍有生成波动。** q518 的最终回归答案值正确、必要来源已在上下文中，仍丢失一篇引用。后续应先记录核验前 supports 并区分逐字引用失配与主证据标记遗漏，再设计通用修复；不能将模型 explanation 中提及的论文直接当成已核验支持。

## 6. 后续修复：脚注显式保留

用户指出页脚过滤可能造成证据遗漏后，核对了当时仅过滤非正文图片的 Git 改动、当前分块器及真实索引。已识别的脚注与普通页眉页脚是不同标签；风险还来自分块器将关联脚注留给图表处理，而单独的表格导出未完整带出这些内容。

## 7. 后续收缩：以可迁移能力为主干

用户要求项目以通用、泛用的形式呈现。将提示词审查纳入修改计划，分层收缩，避免继续把具体训练错题的解题规则写进全局提示词：

2. 离线检查消息、完整原文、单位、来源标签、原图、多值格式及局部降级。
3. 后续用同一索引和模型、固定难题与控制题比较旧版/收缩版的答案值、引用及拒答，再决定是否继续收缩字段与引文恢复策略。单轮小样不能证明没有过拟合，具体错题不能作为生产路由条件。

本轮已实施：

- 主提示词由 1,437 个英文词、30 条规则收缩为 398 个英文词、10 条规则；查询规划由 370 个英文词收缩为 123 个。词数按相同正则统计，均不等同于模型 token 数。

- 合并 schema 字段说明中的重复约束，删除生成消息末尾的重复输出提醒和动态 schema 单位说明；提交单位保留在问题消息中，JSON 字段结构继续完整提供。
- 查询改写仍参与检索及事实融合；不再发送给最终回答模型。`generate_answer` 移除仅为这份重复提示服务的 `facts` 参数，独立读图数据继续作为可出错的辅助上下文，原文/原图优先。
- `generate.py` 从本轮开始时的 924 行减至 775 行，没有新增生产模块或依赖。七个中间输出字段、引用核验、补查一轮、并发及逐题恢复均保留。
- 测试改为核对实际消息、原文、字段结构和模型答案透传，减少对旧提示词固定措辞的绑定；增加提示词长度、数值精度透传和无单位类别答案的检查，并禁止未替换的生成模型调用真实 API。
