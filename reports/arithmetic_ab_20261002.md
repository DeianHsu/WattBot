# 去掉程序复算的小样对照

## 结论

按要求删除了生产代码中的算式执行、自动单位换算和有效数字覆盖，数值答案与计算说明直接采用 LLM 输出。保留证据来源、条件匹配、图表冲突及引用核验，提交格式整理保持不变。

本次十题对照中，旧后处理得分 **0.653333**，直接使用模型答案得分 **0.578333**，相差 **0.075**。差异来自 q022 的数量级换算。八道 Math 题两组官方得分均为 **0.566667**，答案正确数均为 **4/8**。

该小样没有显示删除复算可以提分，也无法据此判断所有问题上哪种方案更好。生产代码仍保留用户要求的无复算版本，未自动恢复旧逻辑。

## 对照方法

- 模型：当前配置的 DeepSeek `deepseek-flash`，关闭思考，温度 0，题目并发 3。
- 样本：固定八道 Math 题，另加两道数量级题；测试开始前固定题号，未根据本轮结果替换样本。
- 每题运行当前生产检索、页面扩展和生成流程，包括已有的一轮缺失事实补查。标准答案、题型标签不进入模型输入。
- 捕获数值后处理前的同一份模型答案，将深拷贝分别交给旧函数与修改后函数。两组共用检索证据、模型请求、引用核验与图表核验。
- 最终轮答案使用同一套提交整理逻辑离线导出。无复算分支的重放结果与真实生产输出逐题完全一致；两组最终引用集合完全一致。
- 使用本地 `input/Score.py` 评分，标准答案来自 `input/train_QA.csv`。标准答案自评分为 1.0。十题全部完成，无 API 失败题被排除。
- 旧函数仅保存在被 Git 忽略的实验目录，用于复核，不再被生产代码调用。

## 关键差异

q022 的问题正文写着 “in million liters”，输入的 `answer_unit` 列给出 `liters`。模型取到了原文的 5.4 million liters，说明中也写明它等于 5,400,000 liters，最终 `answer_value` 却选择了 5.4。

旧后处理识别到数值记录的 `million liters` 与提交单位的 `liters`，将它乘以一百万。删除单位转换后，原始值 5.4 被直接提交。该题的答案分从 0.75 降为 0，引用分与其他部分不变，导致十题平均分下降 0.075。

因此，本轮收益来自旧逻辑的单位转换。八道 Math 题中没有出现复算把正确答案改错或把错误答案改对的计分变化。q029 只从 25 调整为 25.1，两个值均不满足标准答案。

此次有四道题实际通过旧算式执行路径。其他 Math 题涉及原样报告、拒答或旧辅助校验回退。八道 Math 题同分的结论仅适用于这批实际输出，不能外推到全部计算题。

## 后续建议

先加强 Prompt 的提交单位约束：`answer_value` 必须以 `answer_unit` 列为准；问题正文的单位描述冲突时，换算后的提交单位优先。继续沿用 LLM 计算，并明确要求核对答案值与 explanation 中换算后的结果是否一致。

这项提示词修改应单独做对照，以区分“删除后处理”和“加强单位约束”的作用。本次未改动 Prompt，避免混入第二个变量。
