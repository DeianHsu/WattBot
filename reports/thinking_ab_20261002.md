# MiMo 思考开关小样对照（2026-10-02）

## 结论与生产修改

默认关闭 MiMo 深度思考。8 道固定证据的成对测试，两组答案均为 8/8 正确；关闭组没有答案正确转错误或引用 F1 回退。平均计时从 32.95 秒降至 20.14 秒，减少约 38.9%。这是小样的平均规划＋缓存生成时间，不能直接外推全量预测加速比例。

生产修改仅为 `models.py` 的 ChatOpenAI 构造增加：

```python
extra_body={"thinking": {"type": "disabled"}}
```

不更换模型、不调整提示词、输出预算、超时、重试、检索或并发流程。共用客户端的图片描述、查询规划、逐图读取和最终生成默认均为非思考模式；已有图片描述和索引不变，本轮未重新生成描述，因此图片描述质量不在本次对照范围内。

完整管线确认中 q274 曾答错，后续固定薄证据对照两种模式均错；全流程独立复跑两组均通过。最低值题的证据覆盖和图表读数波动仍存在，不能宣称已修好，也不能保证全量关思考后绝无质量损失。

## 1. 对照方法

- 8 题覆盖文本术语、判断、拒答、计算、最低值、表格条件、图例计数及数值范围。每题重复使用同一份真实检索证据和查询，两组证据哈希一致。
- 每组另行调用查询规划并保存实际查询；固定证据生成继续使用保存的查询，隔离检索改变的影响。最后另跑完整管线验证规划与检索的衔接。
- 普通调用分别显式设置 thinking=enabled／disabled，模型、temperature=0、提示词及其他参数不变。开启思考时服务端对 temperature 的覆盖属于实际配置的一部分，此实验比较实际两种模式，不声称纯粹隔离了采样温度。
- 沿用原生产多图流程：独立读图按本组模式调用，随后协调读数的调用两组均显式关闭思考。没有为了实验改变图表处理逻辑。
- 每题两个模式依次运行，不同题最多并发 3 个；调用顺序交替，4 题先开思考、4 题先关思考。未加输出 token 限制，没有把截断或超时结果伪装成错误答案。
- MiMo 只接收问题、预期单位及实际证据；标准答案、金标来源和题型标签仅用于本地 Score.py 评分。内部思考正文没有保存。
- 每题每组分别保存结果、API 用量及时间，支持中断后保留已完成项；诊断脚本位于忽略的 artifacts 目录，没有加入生产监控或新的工程模块。

原始结果：`artifacts/train_fixes_20261001/thinking_ab_cached_20261002/`，共 16 份完成记录。初始拒答样本的旧记录未含 rounds.queries，测试入口在 API 调用前报错；已兼容旧记录并补跑，没有算成模型错误。早期缓存导出未带 ref_url，评分副本按生产规则从 metadata 补齐；拒答使用 is_blank，没有修改模型答案或引用集合。后续测试入口直接输出该字段。
