日期：2026-10-03。范围为静态审查、官方评分重放和通用方案；本轮不修改生产提示词或程序，不加入算术复算或答案内容核验。

状态更新：此文记录修改前的审查。后续已实施三项最小改动，逐步对照和保留／回退决策见 [输出契约修复记录](D:/Study/Pycharm/Projects/WattBot/reports/output_contract_fix_20261003.md)；以下“当前”指审查时的版本。

## 1. 正式评分的要求

训练集共 245 题：163 个数值标量、44 个文字标量、26 个方括号区间、7 个括号列表、5 个不可回答值。该分类仅用于本地审查，不发送给模型，不生成按题号处理规则。

| 输出 | 正式规则 | 当前风险 |
| --- | --- | --- |
| 数值标量 | 相对容差 0.001，绝对容差 0.001；模型按输入单位给值 | 题目显示尺度与预期单位冲突；无要求时随意舍入 |
| gold `[low, high]` | 数值区间可接受一个区间内的标量 | 区间可能只是 gold 容差，问题仍只要一个值；模型看不到 gold |
| gold `(a, b)` | 必须包含全部元素；允许顺序变化 | 联合短语与独立项的容器歧义 |
| 文字标量 | 忽略大小写、标点、首冠词；不做同义词语义匹配 | 额外修饰词、扩写或容器变化可能失分 |
| `is_blank` | 不可回答题的值、引用 ID、URL、支持材料同时清空 | 不能通过“有引用”推定可回答，也不能因引用局部异常清空已有答案 |

`answer_unit` 由输入给出且不计分，但其尺度决定 `answer_value` 应表达的数值。不能把单位列正确理解为数值已经正确换算。`Score.score()` 的引用分使用 F1，`row_bits()["ref"]` 使用 Jaccard，报告应区分。

## 2. 单位与精度

现有提示词已经要求预期单位优先、计算保留中间精度。本轮扩大对照未观察到新增单位换算错误；上一轮 q022 显示这项要求仍有执行波动。

本地官方重放：

- q482：13.0 通过；13.02 和 13.0208333333 未通过。精确运算 30,000 / 96 / 24 的结果约为 13.020833 天，gold 将其近似为 13.0。**天是连续时间单位，可有小数**；单位本身没有整数约束。
- q104：1.33 通过，1.333333 未通过。这也说明单纯增加保留位数无法消除金标准舍入差异。
- q518：原页 off 的 explanation 得出 1,035,930,000，最终舍入到 1,040,000,000，超出 gold 上界。此处过度舍入损失了正确结果。

**通用方案：**题目或原始来源明确规定精度时遵循；离散计数按实际语义输出整数，连续时间等允许小数；无明确精度要求时保留充分有效数字，避免主动粗舍入。必要换算与最终数字完全交给 LLM，程序只做格式整理。

**不能保证的部分：**题目未说明 gold 的近似精度时，通用规则无法保证严格匹配每个标签。不要加入“天一律整数”“所有数值三位有效数字”或根据训练答案选舍入位数等规则。科学推导正确与评分值通过需要分别报告。

## 3. 短语与多值容器

q055 的 gold 是 `prefill and decode`；`(prefill, decode)` 和扩写的阶段名称均未通过。训练说明记录 gold 于 2026-08-17 从括号列表改为原文短语。q451 同样接受 `node and system`，不接受括号列表。另一方面，q432 要求 `(GPT-4, Claude-3.5)`，改成 `GPT-4 and Claude-3.5` 会失分。

所以，“问题里问 two”无法单独决定容器。这个差异在训练集中有多个实例，涉及语义和标注约定；对模型增加思考强度也没有稳定保证。模型输入没有 gold 容器信息，不应伪造这一信息。

当前 `AnswerDraft` 将标量 JSON 数组转换为括号列表；这项容错对真正的多值题有用。`normalize_answer_value()` 还有“问题出现 both/two/range 等词且值含逗号，就自动加括号”的推断，范围过宽。离线反例：

```text
问题：For two hardware configurations, what shared bottleneck was observed?
模型值：memory bandwidth, especially DRAM
当前整理结果：(memory bandwidth, especially DRAM)
```

问题提到两个配置，仍可能只问一个共同瓶颈。这个例子没有调用 API，也没有用标准答案；用于证明关键字推断会改动答案结构。

**通用方案：**下一轮先让模型遵循简短输出约定：类别答案采用原始证据里的简洁标准名称或完整短语，不附可选解释；多个独立结果使用括号列表，约定俗成的联合短语保留为一项。程序只序列化模型明确给出的列表，不依赖题目中的数量词猜结构。

先移除自动括号推断的风险，再评估现有数组容错是否足够；不需要新增复杂路由、题型专用生成函数或按题号映射。对本身存在标注歧义的问题，报告边界，保持泛用性。

## 4. 下一轮可实施的最小范围

按顺序，每次只改一项，保持同一批问题及实际证据，先本地格式用例，再做少量 API 配对：

1. 去掉用 both/two 等词猜测多值的逗号包装，保留真假值、明确范围与模型显式数组的基本格式容错；给单一短语和真实列表各加离线用例。
2. 仅收紧既有输出契约的类别措辞：优先原文标准短名称/短语，避免无必要的修饰与扩写；明确独立结果和联合短语的边界，不列训练答案或题材例子。
3. 仅收紧数值措辞：预期单位决定最终尺度，遵循明确的舍入要求；无要求时不主动粗舍入。保持 explanation 与最终值由同一模型生成，不加程序正确性检查。

没有必要为了本轮问题增加 `numeric_facts`、运算表达式、第二个核算模型、强制引用门槛或题号专用分支。当前 API 输出结构仍可沿用。

每项同时记录答案值通过、语义/口径差异、引用 F1 和耗时，检查正确样本回退；标准答案仅本地评分。存在 gold 精度或容器歧义时不宣称通用规则必然修复。本轮审查没有提前实施上述三项。
