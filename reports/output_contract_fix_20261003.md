# 输出契约三步修改与六题回归

日期：2026-10-03。保持默认 off，按审查顺序实施。生产修改限于既有生成文件和测试，没有新模块、题号分支、标准答案映射、程序复算或答案内容核验。没有重建索引、全量 predict 或 push。

## 1. 删除多值猜测

移除 `normalize_answer_value()` 依靠题目的 both/two/range 等词及逗号推断集合的分支，删除失去用途的 `question` 参数，并更新生产调用。

现在普通逗号、完整短语和已明确输出的集合保持原样。显式 JSON 标量数组仍由原有 validator 转为括号列表，真假值整理为 1/0，明确数值端点的范围仍做既有格式转换。程序不判断答案的语义或精度。

新增离线用例验证逗号短语、带逗号的名称、千位分隔、显式集合，以及题目包含 two 但只有一个共同瓶颈的真实提交路径。该确定性格式缺陷已修复。

同一批六份基线草稿离线重放：核心值、引用和官方评分均未改变。这个结果说明本批草稿没有触发旧的误包装，不能将其计为新增答对。

## 2. 收紧类别措辞

在原有 Output contract 中区分可读的 `answer` 与最小值 `answer_value`。类别使用原文简洁标准术语，保留必要身份信息，避免可选修饰和解释；完整术语／联合短语为单项，独立结果使用 `(a, b)`。

仅替换一小段通用规则，不列题材例子或训练答案，不增加路由或额外生成步骤。本次单独修改后的六题对照未修好两道文字格式题，还观察到一题单位回退，因此继续按计划明确数值单位；没有把该中间状态当作最终改善。

## 3. 单位与精度

明确由模型把最终数值 `answer_value` 转成 Expected unit，优先于题目中的显示尺度。精度遵循题目或原始来源的明确要求；无要求时保留充分精度，避免粗舍入或无依据的额外数字。单位本身不强制整数。

推理段只保留中间精度约束，把最终精度要求集中到输出约定，避免重复堆叠。计算、转换与舍入仍全部由 LLM 完成，程序不重新计算或改变结果。

最终保留这一版本：六题答案值 4/6，与修改前相同；原本通过的四题本次均保持通过。来源分有所改善，但尚无答案值提分证据。

## 4. 分步对照

固定六题 q055、q432、q104、q482、q518、q022，均来自之前已测试的训练题。模型收到当前问题、预期单位和已保存的真实论文证据；金标准及题型标签仅用于本地评分。全部调用 DeepSeek，显式 off。

冻结正文、表格原页、图片及动态问题消息，各阶段的证据消息 SHA256 一致。辅助读图若触发只在冻结时执行并共用；本批未触发。格式步重放同一份草稿，无 API 调用；基线、类别、精度及追加契约试验各六次，总计 24 次最终生成、6 个不同问题。

引用采用正式 F1 和 `Score.score()`，没有将逐行 Jaccard 用作总分。每格一次，不是统计保留集，也不能证明全量性能或稳定性；不重新检索、补查，因此仅评价固定证据下的输出。

## 5. 追加试验及回退

第三步仍有文字格式问题，所以另测试一次更强的通用说明：明确独立实体名称的列表表示、最短无歧义术语，并同步到已有 `answer_value` 字段说明，没有新字段。

这个试验使 q432 输出 `(GPT-4, Claude-3.5)` 并通过，但 q104 从 1.33 变成 1.3333333333333333。其计算更精确，与 gold 1.33 的差异约 0.25%，超过正式容差，导致原正确控制题回退。q055 则输出 `(prompt prefill, autoregressive decode)`，仍未通过。

没有答案值净改善，且观察到控制题回退，所以撤回这处追加的系统／schema 说明，保留第三步版本。没有按题号把 q104 强改回 1.33，也没有将所有值统一舍入。

## 6. 未解决项及泛用边界

- q055 能识别两个阶段，但当前措辞与 gold `prefill and decode` 不一致；部分扩写本身也出现在原文中，不能单纯认定为幻觉。该题的列表／联合短语标注还存在歧义。
- q432 能识别两个模型，最终保留版本仍用自然语言连接，未满足该题 gold 的列表表示。更强契约单次修好它，却没有总体答案值收益，暂不作为默认。
- 数字精度：更精确的结果与隐含舍入标签可能不匹配，无法通过“更多小数”“天一律整数”或统一有效数字规则可靠解决。此限制保持透明，不加入金标准偏好。
- 三项通用代码／提示约定已实施；上述具体错题尚未全部修复。现阶段不应宣称六题全对或保证 Kaggle 提分，也不宜继续围绕这几题反复增加全局规则。
